# 鏡行式｜展場互動

觀眾用手機挑一隻小夥伴，幫它加上自己的照片和 emoji，再留一句話。送出之後，作品就會飄到展場的大螢幕上，跟其他人的作品一起漂浮、碰撞，輪流放大顯示留言。

不用下載 App，也不用註冊，手機掃 QR code 就能玩。

## 觀眾怎麼玩

1. **選擇小夥伴**：嘿嘿團團、啊啊扇扇、嗯嗯圓圓、哼哼刺刺、呵呵方方，五隻挑一隻
2. **裝飾**
   - 從相簿加一張照片，背景會**自動去掉**（大約 10～30 秒）
   - 加 emoji：可以從選單挑，也可以按 ⋯ 用手機鍵盤輸入任何 emoji
   - 每個東西都能用手指拖曳、旋轉、縮放，也可以用下面的按鈕微調位置和前後順序
   - 畫布左上角有**復原 ↶ 和重做 ↷**，放錯了可以退回去
3. **發聲**：輸入暱稱（10 字內）和想說的一句話（20 字內，可以不寫）
4. **完成**：作品送到大螢幕上，也可以分享或存到手機

> 第一次去背需要先下載去背工具，比較久，之後就會快很多。去背不滿意的話，可以按「編輯」改用原圖或換一張照片。

---

## 大螢幕怎麼運作

- 作品在畫面上隨意漂浮，互相碰到會彈開（像 DVD 待機畫面）
- **新作品先上場**：有人送出作品，會依序飄進畫面
- 畫面上的作品會輪流**放大**，下方顯示暱稱和留言（有留言的作品優先）
- 作品比畫面放得下的還多時，會每隔一段時間換一批上場，每個人都有機會被看到
- 作品還很少的時候，會先用小夥伴吉祥物補位，畫面才不會空

**開啟方式**：用電腦打開大螢幕網址，點一下畫面就會進入全螢幕。

### 現場微調（不用改程式）

在大螢幕網址後面加上參數就能調整，例如：

```
https://dcat116-mirroring.vercel.app/screen.html?max=15&speed=50&spot=8
```

| 參數 | 意思 | 預設 |
|---|---|---|
| `max` | 畫面上最多同時幾件作品 | 12 |
| `speed` | 漂浮速度，數字越大越快 | 60 |
| `spot` | 每幾秒換下一件作品放大 | 7 |

建議 `max` 不要超過 20，太多會擠成一團。大螢幕會輪播**最新的 200 件**作品。

## 管理員怎麼用

打開作品管理頁，按「**用 Google 登入**」。只有被加進管理員名單的 Google 帳號才能管理作品，其他人登入了也沒辦法刪除。

管理頁有三個分頁：

| 分頁 | 可以做什麼 |
|---|---|
| **作品** | 看所有作品；看到不適合的內容按「刪除」，大螢幕上會立刻消失 |
| **垃圾桶** | 被刪掉的作品會先放在這裡，寫著是誰、什麼時候刪的。可以按「**復原**」放回去，或按「**永久刪除**」徹底清掉 |
| **歷史紀錄** | 每次刪除、復原、永久刪除都會記錄下來：哪位管理員、幾點、對哪件作品做了什麼。紀錄沒有人能改或刪 |

> ⚠️ 永久刪除後就救不回來了。垃圾桶不會自動清空，需要的話請手動清理。

### 新增或移除管理員

管理員名單存在 Firebase 的安全規則裡，不在程式碼裡：

1. 打開 [Firebase 主控台](https://console.firebase.google.com)，選專案 → Firestore Database → **規則**
2. 找到 `email in [...]` 那一行，在方括號裡加上或刪掉 Google 信箱，每個信箱用引號包住、用逗號隔開
3. 按「發布」，大約 1 分鐘後生效

> 本機的 `firestore.rules` 也要一起改，下次更新規則時才不會蓋掉。這個檔案含有管理員信箱，所以不會上傳到 GitHub；GitHub 上的 `firestore.rules.example` 是把信箱換成範例文字的版本。

## 展場當天檢查清單

- [ ] 大螢幕的電腦連得上網路，打開大螢幕網址、點一下進入全螢幕
- [ ] 拿一支手機實際走一次流程，確認作品有出現在大螢幕上
- [ ] 管理員手機或電腦登入管理頁，隨時可以刪除不當內容
- [ ] 把測試用的作品刪掉，再到垃圾桶永久刪除
- [ ] 展場的 Wi-Fi 或手機網路正常（去背工具第一次要下載，網路慢會等比較久）
- [ ] 大螢幕**不要設定每幾秒自動重新整理**，會很快用掉免費額度

## 常見問題

**觀眾送出後，大螢幕沒有出現作品？**
新作品會排隊進場，每 2.5 秒放一件。如果一直沒出現，重新整理大螢幕頁面試試。

**去背一直轉圈圈或失敗？**
通常是網路太慢或照片主體不明顯。可以等一下，或按「編輯」改用原圖、換一張照片。

**管理員按刪除，出現「這個帳號沒有管理權限」？**
登入的信箱不在管理員名單裡，或是信箱打錯了。照上面「新增或移除管理員」的步驟檢查。

### 在自己電腦上跑

需要先安裝 [Node.js](https://nodejs.org)。

```bash
npm install
npm run dev
```

終端機會出現 `Network: http://192.168.x.x:5173`。手機和電腦連同一個 Wi-Fi，手機打開這個網址就能測試。

- **有 `.env` 檔**：會連到 Firebase，跟線上網站用同一份資料
- **沒有 `.env` 檔**：改用本機測試模式，作品存在 `.local-data/` 資料夾，不用登入就能測管理頁。刪掉這個資料夾就會清空

`.env` 的格式請參考 `.env.example`，內容從 Firebase 主控台 → 專案設定 → 你的應用程式 → SDK 設定 複製。

### 常用指令

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開本機測試網站 |
| `npm run build` | 打包成正式版（Vercel 會自動跑，平常不用手動） |

### 檔案在哪裡

| 想改的東西 | 檔案 |
|---|---|
| 小夥伴的名字、介紹、emoji 選單 | `src/data/characters.js` |
| 手機每一步的畫面 | `src/phone/screens/` |
| 手機的樣式（顏色、大小、間距） | `src/phone/phone.css` |
| 大螢幕的動畫和輪播規則 | `src/screen/BigScreen.jsx` |
| 管理頁 | `src/admin/main.jsx` |
| 存取作品的方式（Firebase／本機） | `src/lib/store.js` |
| 誰可以讀、寫、刪資料 | `firestore.rules`（範本：`firestore.rules.example`） |

### 安全規則重點

Firebase 的安全規則決定誰能做什麼。改了 `firestore.rules` 之後，要貼到 Firebase 主控台發布才會生效：

- 任何人都能**送出**作品和**看**作品，但格式要正確（圖片大小、字數、時間都會檢查）
- 作品送出後**不能修改**
- 只有管理員能刪除、復原、永久刪除作品，也只有管理員看得到垃圾桶和歷史紀錄
- 歷史紀錄只能新增，**寫進去之後誰都不能改**，管理員也不行

### 不能上傳到 GitHub 的檔案

`.gitignore` 已經設定好，下面這些不會被上傳：

- `.env`：Firebase 設定
- `firestore.rules`：裡面有管理員信箱
- `.local-data/`：本機測試的作品
- `node_modules/`、`dist/`：可以重新產生的檔案
